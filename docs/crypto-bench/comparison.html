6 项统一使用 Go 的 Sign / Verify 接口，每次操作调用一次 C 后端；Go、CGO 和完整签名 / 验签调用成本均计入。结果来自本机 macOS ARM 实测，不能当成 Linux Intel 数据，也不是 TRON / Sui 客户端实测。

私钥列是完整原始 / 展开编码，非运行时内存。Sui 钱包备份可为 32 bytes 种子，本表 ML-DSA-65 展开私钥为 4,032 bytes；两者不可混作同一表示。Falcon 采用 TRON 的无头公钥 / 私钥主体 896 / 1,280 bytes；协议签名是带头的 617–667 bytes，不能与 TVM 的 666 bytes 去头补零槽混用。SLH 私钥 64 bytes 包含公钥 32 bytes。ECDSA 签名 64 bytes 不含恢复信息。ML-DSA-44 / 65 分属 NIST 类别 2 / 3；速度不是安全等级。

统一了哪些边界

  • 同一 Go 可执行文件、单线程顺序测试；GOMAXPROCS(1)、LockOSThread，计时循环预分配缓冲区并关闭 Go GC。没有在 C 内部批量操作以摊薄 CGO。
  • 同一份 4,096 条 32 bytes 公开消息，顺序逐项一致；每项 5 轮 × 7 批，每批签名 32 次、验签 256 次。每轮换钥并轮转顺序。
  • ECDSA 签署 32 bytes 摘要；其余签同一 32 bytes 原始消息。ML / SLH 是 Pure、空上下文，内部哈希计入。安全随机数、拒绝采样、签名编码与验签均不省略。ECDSA 是确定性 nonce，ML / Falcon 读取系统新熵，SLH 使用 OpenSSL 安全 DRBG；随机数需求与实现不同，不宣称等量随机计算。
  • 密钥初始化在计时外，签名 / 验签内存对象可复用。Falcon 动态签名每次重新解码和计算；未隐藏 FFT expanded-key 缓存。热密钥、小工作集的稳态测试，不代表大量冷公钥或区块吞吐。
  • 共同 C 编译参数：-O3 -mcpu=apple-m1 -DNDEBUG -fno-fast-math -ffp-contract=off。各库保留适合 ARM 的汇编 / NEON，编译选项相同不代表内部优化程度完全相同。
  • ECDSA 用 libsecp256k1；ML 两参数用同一 mldsa-native；Falcon 用原版 Falcon NEON，不是旧表的 FN 候选；SLH 用 OpenSSL C / ARM SHA-256。没有 JVM、Rust 或 C++ 包装进入主测试。

线程 CPU 由相同 CGO 时钟接口读取，锁定同一 OS 线程；另存墙钟及进程 CPU。macOS 不保证固定性能核和频率，环境、电源与温度快照保存在原始数据中。

验证与判断

每轮 32 个正例及消息篡改、签名篡改、截短、错钥四类负例；所有计时调用检查成功，签名每批末重新验签。ML 两参数与 OpenSSL 互验；Falcon 通过公开 Falcon KAT 及 NEON 上游测试。每项正式签名 1,120 次、验签 8,960 次。原始数据复算同时检查语料索引、次数、尺寸、顺序和 ECDSA 倍数。

应期待 SLH-128s 签名较慢但输出更小，128f 签名更快但验签不一定快；ML-65 比 ML-44 使用更大参数；Falcon 小签名与快速验签需付出更复杂的采样成本。公开评测用于检验量级和解释差异，不把某次历史排序强行当作结果。
