分布式账户压测：本地功能验收

三种账户的准备、创建、转账与回执核对均通过。中控按总 QPS 分配负载，客户端保留独立公私钥；PQ 使用公钥位于 storage 的合约账户。

测试范围

macOS arm64，Node.js v25.9.0；本地 3 个 validator、1 个 Bundler、1 个 Bench 客户端。每种算法 3 个账户、6 次转账，2 个工作线程，目标发送上限 5 QPS。记录时间：2026-11-02T09:29:51.634Z。

这是功能回归的小样本，包含尾部回执等待，不能据此推断最大 TPS 或三台真实机器能否达到 100 QPS。全局 100 QPS 分为三份的逻辑已通过离线测试；真实机器的签名、模拟、网络和出块容量仍需实测。

正确性检查

  • 每账户独立公私钥，文件权限 600；创建和转账前后密钥保持不变。
  • PQ 创建后核对合约公钥；每组 6 次 1 wei 转账，收款账户准确增加 6 wei。
  • 同一账户串行、不同账户并发；重复 run 被拒绝，重复创建跳过已有账户。
  • 模拟未记录完成的充值与转账，核对真实回执后恢复；未核定任务阻止下一轮发送。
  • 三种算法各补测 6 次转账，单 worker 缓存 3 个账户，均命中 3 次、未命中 3 次；nonce 与收款余额正确。
  • 收到停止信号后停止派发，等待在途操作；预约开始前停止时不发送交易。余额与成功回执一致，恢复核对不重发。
  • 6 项限速、缓存与账户池测试、43 项远程管理离线测试、19 项原有 one-box 回归全部通过。

签名侧优化与空间

已实现：保留多 worker 并发，新增有上限的账户对象缓存，并在 Bench 内省去 SLH 的真实占位签名。真实操作依然逐笔签名、验签和查询 nonce；不缓存签名或复用 nonce。

以下诊断在本地链停止后进行，Apple M1 Pro、纯 JavaScript noble-post-quantum 0.7.1。每项完成相同的 12 条消息签名与验签，密钥生成和预热不计时。

Workers流程墙钟有效签名吞吐进程 CPU
1真实占位签名＋真实操作签名33.94 s0.35 /s33.81 s
1仅真实操作签名17.22 s0.70 /s16.95 s
2仅真实操作签名8.62 s1.39 /s17.07 s
4仅真实操作签名5.10 s2.35 /s18.75 s

省去重复签名使单 worker 的耗时接近减半；在优化后单 worker 基础上，4 个 worker 的吞吐约提高 3.38 倍。这是一次小样本诊断，不是链上 TPS，也不保证在其他 CPU 上线性增长。采样 RSS 约 74–125 MiB，反映本诊断进程，不能作为完整 Bench 的内存预算。原始统计、依赖版本与脚本摘要。

内存用在反复使用的数据上。每个 worker 默认缓存 64 个账户，使用 --cache-accounts 调整，0 为关闭。缓存仅包含身份与钱包对象，不是 SLH 内部树节点预计算。大量只使用一次的账户，扩大缓存帮助不大；三种算法的热账户复用测试均已通过。

进一步优化优先看实现。当前 SLH 使用 JavaScript SHA-2；下一步值得比较使用硬件 SHA 指令的原生实现，并考虑常驻签名进程。ML 当前每次调用原生 helper 都启动进程，也有复用空间。更换后端须保持 Pure 模式、上下文和编码一致，并通过标准向量及双向验签验证；本次尚未替换后端。OpenSSL SLH-DSA 接口。

算法内部也有空间，但需要专门实现。根据 SLH 的树结构，可探索并行计算独立子树、缓存热密钥的可复用树节点；消息摘要决定的签名工作仍需执行。树缓存应按完整密钥和树地址隔离，保留现有随机化策略与每笔签名计算。128s 侧重短签名，换成 128f 属于改变参数方案，不是同一算法参数下的无代价加速。FIPS 205。

已有环境升级检查

升级包现在校验新 Bench 必需文件；升级时补齐每台 Bench 的连接配置，执行三种算法的准备、创建和转账后才标记 ready。该验收动作已在本地三节点链上实际执行通过；本地仅替代了 systemd 状态与目录映射，没有替代链上交易。

远程 SSM 分发和目标机性能尚未由本次本地测试验证。已有环境使用 upgrade 保留数据和密钥，无需 reset；这是整套发布，会滚动重启 validator 和重启 Bundler。脚本更新可复用有效的 Linux 构建缓存。

使用和复现

中控使用 tools/cluster load，按 prepare → create → transfer 执行，通过 status 查看进度、stop 停止、reconcile 核对未决请求。原有部署与 Bench 入口保持兼容。

node --test tools/chain-bench/load/core.test.mjs
python3 -m unittest discover -s one-box/remote -p 'test_*.py'
node tools/chain-bench/load/integration.mjs <已启动的环境名>
