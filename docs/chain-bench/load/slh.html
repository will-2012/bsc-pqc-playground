SLH-DSA-SHA2-128s：账户创建与转账压测

完整链路约 30.6 UserOp/s，直接提交约 224 UserOp/s。前者主要受模拟与打包限制，后者已用满混部署机器的 CPU，主要开销在 Bench 签名；两者都不是独立链容量。

环境与口径

2026-11-03–04，三台 Linux x86_64 机器，每台 8 个逻辑 CPU，同机运行 Bench、Bundler 和 Validator。链数据与 ML 测试沿用同一环境，区块 gas 上限为 2.1 亿，出块间隔 450 ms。账户采用 v7 storage 合约，复用现有 SLH 预编译；算法为 Pure SLH-DSA-SHA2-128s、空上下文。基于 2ba468f，叠加本次可选 SIMD 签名后端；链上合约与预编译不变。

每个账户保留独立公私钥和部署记录；私钥为 64 bytes、公钥为 32 bytes、签名为 7,856 bytes。准备阶段生成密钥并预充值，创建阶段通过真实 UserOperation 部署合约。转账从完整一万账户池中随机选择其他账户作为收款方，排除自身。密钥、连接配置和原始日志仅保留在私有运行目录。

转账每轮派发 300 秒后等待回执收敛。表中实际 UserOp/s＝最终确认数 ÷ 300 秒；gas 与整机 CPU 取运行第 30–290 秒内的完整监控窗口。成功回执与最终化分别观察，目标 QPS 是发送上限。各档为单轮摸底，不将小幅差异解释为稳定收益。

更多在途请求改善了创建速度，继续抬高目标未带来收益。首段签名调用均值约 360 ms、回执等待约 2 s，8 个在途操作基本占满。调至 32 后，窗口吞吐从约 7.87 增至 13.14 个/秒；再将目标翻倍，吞吐没有明显提高。链 gas 仍约 1%–2%、CPU 未满，后续应优先验证模拟与批次等待，而不是增加链预算。

Factory 操作仍按原有规则验证；已部署账户的有界并行验证不适用于带 Factory 的创建操作。没有放宽信誉、存储访问、nonce 或签名检查。每次创建成功后核对代码与链上公钥；最终还逐台核对账户标志、密钥编码、公私钥对应关系及地址、公钥唯一性。

签名器优化对照

同一台空载测试机器、同一 32 bytes 消息接口的小样本中，OpenSSL 签名加本地验签约 297 ms，AVX2 约 111 ms；原 JavaScript 实现约 1,344–1,387 ms。每组仅 4 条消息，用于定位开销，不能直接推算整条链路的加速倍数。

AVX2 实现来自 parallel-sphincsplus 固定提交，已通过上游密钥生成、签名已知答案、SHA-512 和上下文测试，以及跨实现验签和篡改负例。算法、参数、签名大小不变；每个签名进程只用一个 OS 线程，在内部并行计算独立哈希，使用系统随机数。链上仍由原预编译验签。

AVX-512 实现采用同仓库的另一固定提交，同样通过上游测试与跨实现验签，并完成真实账户创建和转账验收。构建脚本固定源提交、归档摘要和编译参数，记录二进制摘要；各后端显式选择，不自动替换基线。后端对照固定账户池，各轮并发与运行时参数分别列明。

核查与收尾

先检查一万账户的独立密钥、公私钥关系及地址唯一性，再核对交易日志与链上回执。代表性的完整链路与直接提交轮次逐条检查操作哈希、发送者与 nonce 组合无重复；这些代表轮次各抽 96 笔独立复算签名哈希、跨实现验签，并核对收款调用、链上公钥、成功事件及规范最终化区块。原始日志和核查记录保留在私有运行目录。

压测结束后停止 Bench，保留账户池、密钥和链数据；撤回临时源码覆盖、RPC、GC、内存和验证并发调整，检查 Validator / Bundler、交易池和最终化。可复用的签名后端与有限 RPC 截止时间通过显式选项提供。
