x86_64 预编译定价复核

本轮支持保留 ML-DSA-44 的 10,000 gas、SLH-DSA-SHA2-128s 的 60,000 gas 实验价格。依据当前部署实现，在空闲 AMD 节点重复测量；没有修改链上价格。ML 的 AVX2 优化有明显收益，需作为另一种实现单独评估。

2026-11-04，Linux x86_64，AMD EPYC 9R14，8 vCPU、标称 64 GiB。目标机旧节点已停止，测前 CPU 忙碌率及 steal 采样均为 0%；没有运行 Validator、Bundler 或发压程序。此次是 AMD 实测，不能代表所有 Intel / AMD 机器。

实际客户端：以 ECRECOVER 定价

同一 Go 测试框架直接调用客户端 Run，包括输入解析、对象分配、验签及返回值。ECDSA 基线为 ECRECOVER，恢复公钥并计算地址，主值 41.21 us, baseline，3,000 gas。表中有效验签 CPU 合并两颗核、GC=100 的 14 轮样本取中位数；定价另覆盖 GC=50 对照。

编译与 x86_64 优化核查

  • ECDSA：沿用 BSC 的 libsecp256k1 / CGO 实现及 64 位运算，使用正常 Go 优化构建，无 -N -l。同组已知公钥验签为 37.12 us；它与 ECRECOVER 不同，不用于本次定价分母。
  • ML：部署使用 mldsa-native v2.0.0 的可移植 C 后端，OPT=0 AUTO=0、-O3 -fno-fast-math。另以同一固定版本构建 OPT=1 AUTO=1，显式使用 AVX2 / BMI2 / POPCNT 和 generic 调优；没有照搬中控 Intel CPU 的 -march=native。
  • SLH：沿用 Trail of Bits Go v0.1.0，Go SHA-256 在目标机使用 SHA-NI；独立 3.44 s profile 中 blockSHANI 占 CPU 样本 27.5%，同时能看到地址编码、复制和内存分配。当前实现已经使用哈希硬件加速，仍有 Go 对象处理开销。

构建使用 go1.25.0、CGO、GOAMD64=v1。v1 不会关闭 SHA-NI 等运行时分派；ML 优化库则明确要求相应指令。静态库编译器为 cc (GCC) 7.3.1 20180712 (Red Hat 7.3.1-17)；Go CGO 包保留默认 -O2 -g，ML 静态库单独按上述 -O3 参数构建。默认 Go 编译优化与 SIMD 后端选择是不同层次。

正确性与公开资料对照

ML 按 FIPS 204，SLH 按 FIPS 205，均为 Pure、空上下文。正确编码的正例与错消息、尾字节篡改、零签名、伪随机签名、截短、加长负例均通过；计时调用逐次检查返回值；输入不变性另由正确性测试核对。现有用例另验证恰好 gas 可执行、少 1 gas 失败。ML 优化库还通过上游功能测试与 KAT。标准规定算法与编码，不规定耗时或本链 gas；测试通过不等于 FIPS 认证。

mldsa-native 官方评测在同一公开提交的 AMD EPYC 4th gen 数据中，ML-DSA-44 验签为优化 50,052 cycles、非优化 123,598 cycles，约 2.47 倍差距。本次同样观察到优化收益；源版本、编译器、调用边界和计时单位不同，不要求倍数或绝对耗时完全相同，也不拿标称频率把这些 cycles 强行换成 us。公开提交、采集时间和摘要保存在数据文件中。

EIP-1108提供了以 ECRECOVER 为参照校准计算成本、兼顾较慢实现的先例。本项目额外采用的 25% 余量和取整档位是实验选择。签名速度不参与验签预编译报价；完整 ERC-4337 交易还包含 calldata、存储及 EntryPoint 等成本。

口径与复现

单执行 P、锁定 OS 线程、绑定单核、正常启用 GC，所有组顺序运行。两颗核各七轮部署后端，七轮 AVX2 对照，五轮 GC=50 对照，共 26 轮、494 个计时组，每组 1 s。每轮固定种子调整顺序；主时钟是进程 CPU，另存线程 CPU、墙钟和 Go 分配。没有锁频；这些是重复均值，不能当作普适硬件极限。

SLH 读取公开多密钥向量；ML 在计时外换钥，并签署同一消息集合、检查独立标准向量。结果对应热密钥、小工作集。源码基于 2690284；本次基准源码快照、编译参数、依赖、二进制摘要、原始样本及校验结果见 数据记录，操作方法见 复现说明。私钥、机器连接信息及原始调试目录不发布。
